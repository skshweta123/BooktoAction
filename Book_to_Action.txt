Perfect scope for an MVP.
For launching fast with 10 books, the best approach is:

Recommended MVP Architecture
Mobile app: Expo React Native (already started)
Auth: Email/Google login via Firebase Auth
Backend data: Firestore
Book files: Firebase Storage (PDFs private, admin-uploaded only)
Result generation: Precomputed content (not live AI per user request)
This gives you speed, low cost, and predictable output quality.

Why Precomputed Is Best for MVP
Live AI generation on every click adds latency, cost, and inconsistency.
With 10 books and fixed result sections, you can generate once and serve instantly.
Easier QA before app-store submission.
Data Model (Simple and Scalable)
Use these collections:

books
id, title, author, pdfPath, status
goals
id, name (Productivity, Leadership, etc.)
book_goal_content
key: bookId_goalId
fields:
summary3min
keyIdeas[]
framework
actionPlan[]
mistakesToAvoid[]
version, updatedAt
User flow storage:

users/{userId}/sessions
selected goals (max 3), selected book, timestamp
Content Generation Process (MVP)
Step 1: Ingestion (admin-side only)
Upload PDF to storage
Save metadata in books
Step 2: Offline content preparation
For each book x goal pair:

Extract text from PDF (script)
Generate structured sections via AI once
Human review/edit (important for quality)
Save final JSON in book_goal_content
Step 3: Runtime app behavior
User logs in
Selects up to 3 goals + one book
App calls API/Firestore query
Returns precomputed sections instantly
Render in tabs
No user uploads, no runtime AI required.

Goal Selection Logic (max 3)
UI allows multi-select chips
Enforce max 3 client-side
Also enforce max 3 in backend request validation (for safety)
API Layer (optional but recommended)
Even with Firestore, add a thin API (Cloud Functions) later:

GET /books
POST /results with {bookId, goalIds[]}
Returns merged response for tabs
For MVP, app can read Firestore directly (faster to ship), then migrate to API for stricter control.
